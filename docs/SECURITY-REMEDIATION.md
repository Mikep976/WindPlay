## Explicit resource limits

- Plist: 256 KiB parser input (routes lower), 1,024 objects, depth 16, 4,096 object visits, 128 collection entries, 4,096 string characters, 1 MiB charged expansion budget.
- DNS: 9,000-byte datagrams, 16 questions, 64 total resource records, 63-byte labels, 255-byte names, 128 pointer/name steps and 8,192 work units per packet. Receive: 32/source/s and 256 globally/s. Reply: 2/source/s and 8 globally/s. Source accounting capped at 128 entries.
- DACP: active sessions only, maximum 16 retained endpoints, maximum TTL 120 seconds. Sender ID, source address and resolved address must agree.
- RTSP: fixed 8-KiB header buffer. Pair setup 0 bytes; pair verify exactly 68; FairPlay exactly 16 or 164. `/info` binary plist 4 KiB; SETUP/TEARDOWN 64 KiB; text parameters 4 KiB; DMap 64 KiB; image bodies 512 KiB; unknown routes zero. Request admission 32/source/s and 128 globally/s; body admission 1 MiB/source/s and 4 MiB globally/s. Header/idle absolute 60 s; body absolute 15 s; read progress 5 s; response writes 10 s.
- Mirror: accept 15 s, header absolute 30 s/progress 5 s, body absolute 5 s/progress 2 s; frames 2 MiB, configurations 64 KiB; 240 messages/s and 32 MiB/s, plus a separate four-configuration-per-10-second budget. Each axis at most 4,096 pixels and total at most 3,840 × 2,160, including coded SPS dimensions; no more than four reference pictures in accepted SPS.

These are availability budgets, not a claim that a receiver can resist arbitrary traffic volumes. Some deliberately generous per-message bounds can still add up across 16 allowed sessions. Default session count is lower.

## Outstanding release authority and assurance

WP-01 through WP-07 are implemented and regression-tested. WP-08 is **not fully fixed**: there is no configured publisher signing identity or proven artifact-attestation workflow. The release verifier requires timestamped, valid signatures from an explicitly configured certificate; a boolean checklist alone cannot authorize unsigned output. No certificate was created, trusted, purchased, or uploaded on the owner's behalf.

GitHub's [official attestation documentation](https://docs.github.com/en/actions/how-tos/secure-your-work/use-artifact-attestations/use-artifact-attestations) requires Enterprise Cloud for attestations in private repositories. This review has not established that the repository has that entitlement. The repository remains private; no public transparency-log service was substituted.

Independent remediation review, coverage-guided fuzzing, final ARM64 artifact/runtime inventory and inspection, and actual Mac/iPhone interoperability remain unverified. The current strict gate records these limitations rather than claiming production assurance from unit tests. Actual hardware interoperability is necessarily a post-build acceptance task; it cannot honestly be marked complete before a test binary exists.

A private unsigned test build would require an **explicit change to the earlier signed/attested release requirement**, not a claim that WP-08 has disappeared. It must retain all runtime parsing, allocation, authentication, network-scope and test gates, identify the exact source/run/hash, and be clearly labelled experimental. Until that decision or owner-approved signing/provenance provisioning, no ARM64 package is produced.

## First-test containment, after approval

Use a fully patched Surface, Defender enabled, a standard (non-administrator) account, a trusted Private-profile LAN, no VPN/guest/untrusted interfaces, password required and diagnostics disabled. A Windows Firewall inbound rule must be restricted to the WindPlay executable, Private profile, selected local address and preferably the exact Mac/iPhone sender IPs (or the selected local subnet). Do not accept a broad all-profiles/any-remote rule. This app does not silently install firewall rules.

The real-sender checklist must verify discovery, the full 20-character password, Mac extended-display mode, audio/video, reconnect and resolution changes, idle recovery, password rotation, stop/disposal, and Windows identity persistence. Do not weaken authentication or parser bounds to conceal an interoperability failure.
